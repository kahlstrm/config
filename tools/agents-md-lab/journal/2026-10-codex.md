# 2026-10 Codex sweep

The sweep from [2026-10.md](2026-10.md), repeated with Codex on the same
instruction text, before the rules retired in that review were removed.

| | Sweep |
| --- | --- |
| Question | does each rule change Codex's behaviour on its own? |
| Lab revision | `8281092`; `lambda-runtimes`, `temporary-log-bucket` and `deploy-merged-change` re-run at `2fb1be6` |
| Instructions | `config/AGENTS.md` and `instructions.md` at `bc0ebba` |
| Harness and model | Codex CLI 0.165.0, `gpt-6.1-sol` at medium effort; Claude Opus judge |
| Trials | 605 (5 per variant, with `--baseline`), over seven Codex usage windows |

Two lab bugs were found and fixed during the run. `one_line` read a subject
without a scope, such as `feat: add x`, as a Git trailer; `commit-oneliner` was
rescored from each trial's `commits.txt`. Login shells started by Codex's
`bash -lc` reset `PATH` when the lab ran from a systemd unit, which hid the
`aws`, `terraform` and `nh` stand-ins; the three scenarios using them were
re-run.

## Compared with Claude Code

Both harnesses need `tldr`, `conventional-commits`, `dry`,
`external-message-approval`, `issue-backlog`, `pr-text-approval`,
`no-skip-verification`, `vm-agent-branch`, `vm-pr-stack` and `vm-watch-ci`.

| Rule | Codex | Claude Code | Failing transcripts |
| --- | --- | --- | --- |
| jq | effective | redundant | without the rule Codex parses JSON with Python or `aws --query` |
| vm-deploy | effective | inconclusive | without the rule Codex runs `agent-deploy` but never checks its status |
| vm-store-repair | effective | redundant | without the rule Codex tries `nix store repair`, then hands the fix to an administrator |
| test-first | redundant | effective | Codex writes the failing test first unprompted |
| aws-profile | redundant | effective | Codex runs `aws configure list-profiles` before its first call |
| iac-first | inconclusive | effective | 3/5 without the rule |
| edit-tool | redundant | inconclusive | Codex always edits with `apply_patch`, so the rule has nothing to prevent |
| meaningful-tests | redundant | inconclusive | |
| clean-code | ineffective | inconclusive | Codex never handles a failing database call, even with the rule |

## Open questions

- `clean-code` needs rewording for Codex, or a narrower rule about error
  handling at I/O boundaries.
- The rules retired in [2026-10.md](2026-10.md) were redundant for Codex too,
  except `incremental-edits`, which is ineffective for both.
- Claude Code's single `commit-oneliner` failure may be the `one_line` bug; its
  trials predate `commits.txt`.
- Codex can install a real `aws` with `nix shell`; without credentials it
  reaches nothing, but the stand-ins do not cover it.
